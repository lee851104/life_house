## 三、資料格式

- 編碼：**UTF-8 with BOM**；分隔符號：逗號；**51 個欄位，34 個檔案的欄位完全一致**。
- 主要欄位：發生年度、發生月份、發生日期(yyyymmdd)、發生時間(hhmmss)、事故類別名稱、
  處理單位名稱警局層、發生地點、天候名稱、光線名稱、道路類別、速限、道路型態、事故位置、
  路面狀況、道路障礙、號誌、車道劃分設施、事故類型及型態、肇因研判、死亡受傷人數、
  當事者順位、當事者車種／性別／年齡、保護裝備、行動電話使用、當事者行動狀態、
  車輛撞擊部位、肇事逃逸類別、**經度、緯度**。
- `死亡受傷人數` 格式為 `死亡1;受傷0`（字串，需自行拆解）。
- ⚠️ **每個 CSV 檔尾都有 2 列非資料的註記列**：`資料提供日期：…` 與 `事故類別：…`。
  讀取時請濾掉（例如判斷第 1 欄是否為 4 位數年份），否則會混進統計。
  `A1_2024-2026_合併.csv` 與 `合併A2.py` 都已處理掉這 2 列。


## 分數怎麼算

```
風險 = Σ 事故嚴重度 × K(d)  ÷  Σ 路網長度 × K(d)
K(d) = 1 - (d/500m)²                    Epanechnikov 距離核
嚴重度 = 1 + 20 × 死亡人數
分數 = 同層中有多少比例的地方比這裡更危險（百分位）
```

分子分母用同一個核加權，比值才是真正的「每公里有效路網的事故密度」。

**三個必要的修正**，少了任何一個分數就沒有鑑別力：

1. **排除國道與高架**（1.6% 事故）。不排除的話，桃園事故最多的兩個「路口」
   會是國道南向匝道 —— 行人不可能走在那裡，走路安全分數卻被它拉低。
2. **基準只在市界內取樣**。用經緯度 bbox 矩形會有約四分之三的取樣點落在
   新北、新竹或海上，那裡有 OSM 道路但沒有桃園的事故資料，形成假的零風險，
   把整條分布往下拉（實測零風險比例 76%）。裁到市界後降到 20%。
3. **依曝險分 8 層比較**。桃園約三分之一是山地農地，兩年零事故；和市區放在
   同一條分布裡比，市區任何一點都落到後段，五個等第只有兩個用得到。

收縮用「觀測到的路網長度」當證據量而非事故件數：用件數時
`adj = (n·risk + k·med)/(n+k)` 在 risk=0 也恆大於 0，真的安全的地方永遠拿不到
高分，80 分以上的等第形同虛設（實測只有 0.5% 的地方進得去）。

路線模式的基準取樣「隨機路徑」而非「500m 圓內整團路網」：一團路網的 40m
緩衝彼此大量重疊，事故去重後除以總路長會嚴重低估每公里事故率，而實際路線
的緩衝幾乎不重疊 —— 尺度不同，市區路線會一律掉到 1 分。

## 隱私

前端 popup 寫「座標已做 ±25m 偏移以保護當事人隱私」。後端讓這句話成立：
個別事故點回傳的是 md5 決定性偏移後的座標（同一件事故每次偏移相同，
但無法反推真實位置），路口中心點則用真實質心。

## 已知限制

- 只支援桃園市。市界邊緣的曝險會被界外（新北、新竹）的 OSM 道路稍微墊高。
- 路線是自建 Dijkstra（scipy），有處理單行道，但沒有轉彎限制與即時路況。
  用途是「這條路線經過哪些高風險路口」，不是導航。
- 機車路網排除國道；快速公路依 OSM 的 `motorcycle=no` 標籤判斷，標註不全時
  可能納入實際禁行機車的路段。
